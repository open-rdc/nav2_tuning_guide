# オドメトリ・センサーフュージョンの調整手順

Nav2のパラメータチューニングを本格的に行う前に、大前提となるオドメトリの精度を確保するための調整手順を解説します。

## 1. ハードウェアの事前準備
* **タイヤの空気圧確認**: 左右で空気圧が異なると直進性に悪影響が出ます。左右均等に適切な空気圧（目安として自転車と同等程度）が確保されているか、必ず最初に確認してください。

## 2. Rviz2を使った軌跡の可視化
軌跡を比較・確認しながら調整するため、Rviz2で以下の設定を行います。

1. `Global Options` の `Fixed Frame` を `odom` に設定します。
2. `Add` パネルから以下の2つのトピックを追加します。
   * `/odom` （エンコーダ単体のオドメトリ）
   * `/odometry/filtered` （EKFによるフュージョン後のオドメトリ）
3. 各トピックのプロパティで `Keep` を高い値（例: 100000）に設定し、台車を動かしても軌跡の線が消えずに残るようにします。
4. `Shape` で線の色を変更し、2つを視覚的に区別できるようにします（例： `/odom` を赤、`/odometry/filtered` を白）。

## 3. ホイールオドメトリ単体での直進テスト
センサーフュージョン（EKF）をかける前に、まずはエンコーダ（車輪）単体の精度を確認します。

* **手順**: ロボットを直線的に手押し等で走行させ、`/odom` の軌跡が真っ直ぐ取れているか確認します。
* **調整対象パラメータ**: 
  直進しているのにオドメトリが曲がる、または進んだ距離が実測とズレる場合は、足回りドライバ側の設定ファイル（`box_v3.param` など）にあるパラメータを微調整します。基本的に、オドメトリ調整の直接の対象となるパラメータは以下の2つのみです。
  * **`RADIUS`** （タイヤの半径）
  * **`TREAD`** （トレッド幅：左右の車輪間距離）

## 4. センサーフュージョン（EKF）の設定確認
「エンコーダ単体では真っ直ぐ進んでいるのに、EKFを通すと軌跡が湾曲（バナナ軌道など）してしまう」といった現象が起きる場合は、EKF（`robot_localization` 等）の設定ファイル（yaml）を見直す必要があります。

* **対策の方向性**: 
  使用しているセンサの種類や精度、ロボットのシステム構成に応じて、どのセンサのどの成分（並進・回転など）をどれくらい信用するか、適切に役割を分担させるようにマスク設定（`true` / `false` の切り替え）や共分散の値を検証・調整してください。

## 5. 周回テストによる確認
設定が整ったら、実際のフィールドを周回走行させてトータルの精度を確認します。

軌跡を見る際は、以下のポイントを確認してください。

* **赤線（`/odom`）の確認**: エンコーダが直進方向をメインに見ており、回転成分を他のセンサ（IMUなど）に依存させる構成にしている場合、このように周回後に始点と終点がズレた形になっても問題ありません。ただし、「ロボットが直線を進んでいる時に、Rviz上でも線が真っ直ぐ引かれているか」は必ず確認してください。
* **白線（`/odometry/filtered`）の確認**: 最終的に重要になるフュージョン後の軌跡です。この白線の始点と終点がぴったり合えば調整完了（自己位置推定の準備OK）となります。

### 💡 始点と終点が合わない場合の注意点
上の写真のように、パラメータや設定を見直してもフュージョン後の軌跡の始点と終点にズレ（隙間）が生じる場合、パラメータ設定以外のハードウェア起因のトラブルが考えられます。

* **環境や筐体構造によるセンサへの影響（例：熱ドリフトなど）**: 特に防水設計などでロボット内部に熱がこもりやすい構造の場合、内部の温度上昇に伴ってIMUのヨー角が時間経過とともにドリフト（少しずつズレる）してしまうケースがあります。
* ソフトウェア側の数値をいくら弄っても改善しない場合は、電源を入れてからしばらく放置して温度を安定させてから計測する、あるいは冷却性能を高めるといった、ハードウェア側の仕様や環境特性を疑ってみることも重要です。
